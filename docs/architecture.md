# Architecture and engineering decisions

React 19 + TypeScript + Vite serve a same-origin browser application. Cytoscape renders imported topology and identity graphs; scenario transitions are deliberately shown as inspectable transition nodes instead of misleading independent prerequisite arrows. CSS is local and has no external font dependency. Native before/after cards represent computed target counts; there are no fabricated analytics.

FastAPI validates closed Pydantic 2 contracts. SQLAlchemy 2 persists users, memberships, opaque sessions, immutable domain documents, relational snapshot elements, events and jobs. SQLite enables a small local installation; PostgreSQL is the Compose deployment. Alembic revisions 0001?0003 contain frozen DDL, relational backfill and database-level append-only triggers. Future migrations must be incremental.

Snapshot elements project asset, relationship and evidence records into rows indexed by workspace/snapshot/category/external ID. Immutable JSON documents retain exact typed inputs without joins reconstructing a different historical state. Principals and services are typed assets; permissions are typed relationships. Scenarios embed versioned transition rules and targets. Analysis and optimisation records embed the request, engine/rule versions, snapshot ID/hash and result. Audit, catalogue, replay and evaluation records share the versioned document envelope. Seventeen named relational domain tables now project these types with typed query columns and full JSON payloads. They are populated transactionally with canonical records, and composite workspace/record/snapshot foreign keys prevent cross-workspace references. This is a hybrid relational/document schema; individual AND/OR clauses and evidence lists remain JSON within their rule records.

The API inserts durable database jobs. One separate worker processes them serially. Worker restart requeues running jobs; cancellation discards an analysis result or interrupts optimisation between subset evaluations. Analysis cancellation latency is bounded by a single analysis time limit (up to five seconds). Optimisation has a 15-second outer time limit checked between evaluations; an individual evaluation may extend total runtime by its own time bound. This is not a horizontally scalable queue. Redis is unnecessary for this initial workload; multiple workers would require transaction-safe claims and leases before being supported.

NetworkX checks directed network paths for essential service connectivity. The capability engine uses explicit state sets and bounded BFS; network path existence alone never grants attacker capabilities. Essential constraints currently describe network connectivity, not authenticated end-to-end application health. Exact defence selection enumerates at most 12 action candidates, budget/conflict-feasibility checks each subset, preserves essential connectivity, and evaluates remaining target reachability. Greedy is a documented baseline and can miss synergistic multi-action plans. No quantum module exists in this release.

Application and lab Compose projects share no networks or volumes. The lab exposes synthetic canary endpoints, not vulnerable production software. Fixed validation scripts run manually in a lab container. The normal app and worker never execute commands, scan networks, call Docker, fetch imported URLs, or invoke LLM output. A full SQL lab database, instrumented permissions and automated end-to-end lab experiments remain future work.

Reference APIs reviewed: [Pydantic models](https://docs.pydantic.dev/latest/concepts/models/), [SQLAlchemy ORM](https://docs.sqlalchemy.org/en/20/orm/quickstart.html), [FastAPI security](https://fastapi.tiangolo.com/tutorial/security/). Installed APIs are exercised by the test suite; frontend and Docker validation status is recorded separately.

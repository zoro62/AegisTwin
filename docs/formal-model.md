# Formal model v1.0

Let C be a finite set of capability identifiers, R the snapshot relationships, E the evidence records, and S₀ the scenario's initial capability set. A rule r contains alternative prerequisite clauses Pᵣ = {P₁,...,Pₙ}, required relationship identifiers Rᵣ, evidence Eᵣ, effects Fᵣ, a version and assumptions.

A transition fires in one state S iff there exists Pᵢ ⊆ S, all Rᵣ exist in the counterfactual snapshot, and all referenced rule/relationship evidence meets the selected policy. The successor state is S ∪ Fᵣ. Each AND clause must hold in the same state. OR alternatives are independent sufficient clauses. Evidence policy `confirmed` excludes candidate, conflicting, uncertain and expired evidence. `optimistic` admits these explicitly; it is a sensitivity bound, not confirmation. Evidence freshness is evaluated at a recorded UTC time; optional limits.evidence_at pins that time for reproduction. Future-collected evidence is excluded by the confirmed policy. Optimisation pins one evidence time for all before/after subset evaluations. Re-evaluation at a later time can legitimately change results; saved results never change.

Capabilities accumulate monotonically. There is no revocation, credential expiry during an individual run, consumption, privilege loss, attacker choice with irreversible negative effects, or resource contention. Relationship absence means unavailable under this model, rather than unknown reality. A target is reached if its named capability occurs in an explored state. Finite BFS tracks canonical frozenset states, ignores no-effect cycles, and records bounded witness chains. Witnesses are not an enumeration of all attack paths or necessarily the best independent paths.

Bounds: default maximum depth 12, visited states 5,000, wall-clock time 2,000 ms, three witnesses per target. API caps are 30/20,000/5,000 ms/10. Truncation is explicit. A truncated run proves discovered reachability, but does not prove unreachability. Unfired diagnostics list removed edges, rejected evidence and capability deficits against the union of reached states; that union is diagnostic only and never used to satisfy AND prerequisites. Time-based truncation can depend on machine speed. Fixed limits and non-truncated inputs yield deterministic reachable sets and canonical discovery chains.

Optimisation objective: maximise the sum of weights of baseline-reachable targets made unreachable, then minimise implementation cost and number of actions. Costs are integer, nonnegative, and labelled measured/estimated/user-specified. A truncated counterfactual receives zero certified target-blocking benefit. Feasibility requires budget compliance, no declared action conflict in either direction, and preservation of a directed network path for every essential network relationship's endpoints. Exact certificates apply only to the supplied catalogue and complete searches. Changing network connectivity may break application semantics even when a network path remains; those dependencies must be modelled more richly before claiming service health.

Initial fixture evidence is a design assertion. `confirmed` denotes confidence in that synthetic assertion, not measured exploitability. Rules require explicit possession of test identities or simulated admin sessions. Open ports never imply a vulnerability. No real credential, probability, vulnerability scanner, or attack payload is part of the model.

# Threat model and operating boundary

Assets: account password hashes, session cookies, tenant snapshots, evidence, events, saved runs, queue integrity and lab host isolation. Adversaries include an unauthenticated local client, a viewer attempting writes, another workspace's analyst, and malicious uploaded labels/events. Host administrator compromise and malicious Docker images are outside the application trust boundary.

Controls: scrypt with random salts; opaque random 256-bit session tokens stored only as SHA-256 hashes; eight-hour session lifetime; HttpOnly SameSite Strict cookies; per-session CSRF tokens; same-origin checks for writes; role-checked workspace membership on every domain endpoint; worker loads scenario/snapshot in the job workspace; parameterised ORM queries; 2 MB request body cap; bounded closed schemas; React text rendering; escaped HTML report JSON; no raw HTML from imports; no arbitrary URL fetching or executable input; nonprivileged containers with dropped capabilities; separate application/lab networks. Snapshot history rejects ORM update/delete. Audit records capture selected key operations.

Imported URLs and commands are not accepted interfaces. Fixed lab probes reject arbitrary targets, validate every resolved destination before connecting directly to it, and run only in a dedicated bundled container. Private IP validation is defence in depth, not cryptographic enrollment. Do not run this helper in an untrusted private network.

Authentication requests have a single-process limit of 20 per client IP per endpoint per minute; database uniqueness conflicts return 409. Residual risks: rate limits do not persist across restart or coordinate multiple API processes; registration is open to clients who can reach loopback; no MFA, account recovery, invitation workflow, remote TLS setup or password rotation UI; audit coverage is partial; schema immutability is enforced by ORM guards and SQLite/PostgreSQL triggers; a database owner able to remove triggers can tamper with history; hashes detect accidental differences but are not signed attestations. The durable queue supports exactly one worker; running two is unsupported. Resource limits do not provide an OS-level memory sandbox. Listing records is unpaginated. CSP intentionally prevents framing; API Swagger assets may need a separate development policy. Do not expose this capstone service publicly without hardening and security review.

No real credential harvesting, persistence, evasion, destructive operation, arbitrary shell endpoint, Docker socket mount, public network scanning or autonomous exploitation is implemented.

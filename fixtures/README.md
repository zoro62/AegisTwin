# Fixture provenance

Generated by `python -m scripts.export_fixtures` from `backend/fixtures.py`. Ten typed assets, ten relationships, five finite transition rules, three initial-capability scenarios and four defensive actions. All asset identifiers are synthetic and scoped to a snapshot. No public IPs, real credentials, CVEs or vulnerability claims are present.

`inventory.json` is directly importable. `scenarios.json` is an array of examples: replace each `snapshot_id: "pending"` with the returned inventory snapshot ID and submit each scenario separately. `actions.json` contains the catalogue used by the planner. Regeneration changes collection/expiry timestamps; a fresh import creates a new immutable snapshot. Existing analyses remain tied to their original snapshot.

Ground truth is hand-declared within this finite model: excessive exposure reaches canary with an assumed admin session; overbroad permission reaches canary with an assumed test identity; proxy-only initial control does not confer app control and cannot reach canary. These are model cases, not a representative real-world attack dataset.
